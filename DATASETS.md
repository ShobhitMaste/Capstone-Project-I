# FedTrap dataset guide (Ayush's playbook)

Target: `data/dataset/<class>/*.jpg` with **5 classes** and **≥300 images each**
(minimum 100 to start training; 300+ to reach the 85% gate comfortably):

| class       | policy (demo crop) | primary sources |
|-------------|--------------------|-----------------|
| grasshopper | capture            | Insects Recognition (Kaggle) + IP102 locust/grasshopper classes |
| beetle      | capture            | ArTaxOr `Coleoptera` (crop to bounding box) + IP102 beetle classes |
| moth        | capture            | Butterfly & Moths 100-species (Kaggle) — moth species only; ArTaxOr `Lepidoptera` (manually sieve moths) |
| honeybee    | release            | BeeImage / Annotated Honey Bee Images (Kaggle) + iNaturalist *Apis mellifera* |
| butterfly   | release            | Insects Recognition (Kaggle) + Butterfly & Moths 100-species — butterfly species |

## Sources (verified Sept 2026)

1. **IP102** — the benchmark we cite in the report ([paper repo](https://github.com/xpwu95/IP102)).
   Easiest download is the Kaggle classification mirror:
   `rtlmhjbn/ip02-dataset` (there is also a YOLO-format mirror
   `leonidkulyk/ip102-yolov5` for later detection work). 75k images, 102
   species-level pest classes — we take only the classes that map to
   grasshopper/beetle/moth. **Careful: many IP102 classes mix larvae
   (caterpillars/grubs) with adults — keep adult images only**, since the trap
   camera will see adults.
2. **ArTaxOr** — [Arthropod Taxonomy Orders Object Detection Dataset](https://www.kaggle.com/datasets/mistag/arthropod-taxonomy-orders-object-detection-dataset)
   (Kaggle, `mistag/...`): 15k high-quality images labeled by ORDER with
   bounding boxes: Coleoptera = beetles, Lepidoptera = butterflies+moths,
   Hymenoptera = bees/wasps/ants. Crop each image to its bbox (the download
   script does this) so the classifier sees the insect, not the background.
   Note: no Orthoptera — grasshoppers come from sources 1 and 3.
3. **Insects Recognition** — [Kaggle `hammaadali/insects-recognition`](https://www.kaggle.com/datasets/hammaadali/insects-recognition):
   Butterfly / Dragonfly / Grasshopper / Ladybird / Mosquito, ~1k per class.
   Take Grasshopper and Butterfly folders directly. (Ladybird is a nice
   HOLD-OUT test class later: a beetle we would *release* — species-level
   selectivity demo.)
4. **Honey bees** — Kaggle "The BeeImage Dataset: Annotated Honey Bee Images"
   (`jenny18/honey-bee-annotated-images`, ~5k hive-camera bee crops). These
   are top-down hive shots; balance them with ~100 iNaturalist *Apis
   mellifera* photos (inaturalist.org → search species → filter
   research-grade → export/download) so the class isn't all one viewpoint.
5. **Butterfly & Moths Image Classification (100 species)** — Kaggle (search
   that exact title; `gpiosenka/...`). Species names in folder names let you
   split moth species vs butterfly species automatically.
6. **Your own trap images — the highest-value source.** Once Akshat's camera
   is mounted: photograph printed cards / preserved specimens through the
   actual trap chamber, ~50–100 per class. These fix the domain gap
   (lighting, background, distance) that no internet dataset covers.

## How to download (one-time setup)

```bash
pip install kagglehub
# kaggle.com -> Account -> Settings -> API -> Create New Token -> kaggle.json
mkdir -p ~/.kaggle && mv ~/Downloads/kaggle.json ~/.kaggle/ && chmod 600 ~/.kaggle/kaggle.json

python scripts/download_datasets.py            # downloads + assembles data/dataset/
python scripts/prepare_dataset.py              # per-class counts + sanity check
```

The script assembles what it can automatically and prints what needs a manual
pass (the moth/butterfly sieve, IP102 adult-only filtering).

## Rules that keep the experiment honest

- **Split before augmenting** — train/val/test split at image level first;
  augmentation only ever touches the training split (pretrain.py handles this).
- **Report class counts** before/after balancing in the report (Sec. 3.11).
- Keep trap-camera images **separate** (`data/trap_val/`) — evaluating on them
  separately is the "benchmark vs deployment" story for the paper.
- Non-IID splits for experiments are generated by
  `experiments/run_comparison.py --skew ...` from THIS dataset — never
  hand-pick which images go to which client.
